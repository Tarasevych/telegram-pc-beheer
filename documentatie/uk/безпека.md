# Безпека і захист приватних даних

## Розмежування приватних і відкритих даних

| Категорія даних | Місце приватного зберігання | Що міститься у відкритому сховищі |
|---|---|---|
| Ключ доступу бота | Сховище облікових даних Windows | Лише назва служби та ідентифікатор запису |
| Числовий ідентифікатор власника в Telegram | Локальний файл `instellingen.json` | Умовний приклад для зразка |
| Адреса, користувач, порт і шлях до ключа SSH | Локальний файл `ssh-doelen.json` | Порожній шаблон `[]` |
| Особистий ключ SSH | Стандартна локальна тека ключів користувача | Ніколи не публікується |
| Дані сеансу MTProto та ключі застосунку | Окремий закритий проєкт | Ніколи не публікується |
| Журнал аудиту та потік подій | Локальна тека `gegevens/` | Лише структура полів і схема |
| Ключі доступу та ідентифікатори розумного дому | Закрите сховище відповідного перехідника | Ніколи не публікується |

## Модель загроз і засоби протидії

- **Захоплення облікового запису власника в Telegram:** зловмисник потенційно міг би діяти від імені власника. Засоби захисту: двофакторна перевірка в Telegram, регулярний перегляд активних сеансів у розділі «Пристрої», короткий строк дії кнопок підтвердження, локальний журнал аудиту та можливість миттєвої аварійної зупинки служби.
- **Компрометація ключа доступу бота:** ключ необхідно негайно відкликати через `@BotFather`, записати новий ключ до сховища облікових даних Windows і перезапустити завдання `TelegramBeheer`.
- **Спроба підстановки небезпечних команд у Codex або оболонку:** будь-яка команда PowerShell потребує окремого ручного підтвердження кнопкою; середовище Codex обмежене визначеною робочою текою; текст виводу автоматично очищується від випадкової появи ключів і паролів.
- **Підміна віддаленого вузла SSH:** використовується сувора системна перевірка файлу `known_hosts`; ніколи не вимикайте параметр `StrictHostKeyChecking`.
- **Повторне надсилання старого підтвердження:** кожен одноразовий код підтвердження прив'язаний до ідентифікатора власника, діє лише 120 секунд і видаляється одразу після першого натискання.

## Аварійне зупинення служби

```powershell
Stop-ScheduledTask -TaskName TelegramBeheer
```

Після будь-якого підозрілого випадку обов'язково перевірте перелік під'єднаних пристроїв у Telegram, ключ доступу в `@BotFather`, записи у сховищі облікових даних Windows, файли `authorized_keys` на віддалених вузлах і локальну базу даних аудиту SQLite.
